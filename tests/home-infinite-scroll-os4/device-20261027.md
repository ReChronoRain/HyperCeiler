# 2026-10-27 无限滚动修复验收

环境为 Xiaomi 15、OS4.0.0.22、桌面 8.01.02.8584，原有抽屉模式，14 个桌面页面。
修改保留在 os4-personal，未提交或推送。

## 复现与根因

- 原开关为开启，system_server 仍加载 20261026 接口，capabilities 为 0x3f
  原生缓存收到无限滚动关闭，授权重启后接口与客户端均为 20261027，capabilities 为 0x7f，设置正确下发
- 原实现只接受 goBallistic 的直接返回位置，实际经过透明 parent physics 转发器
  实测转发返回位置为 0x15bd654，旧规则拒绝为 unrelated caller
  转发指令、虚表选择器与栈根改为运行时校验，不把此位置写成生产常量
- 首尾释放存在正常回弹，实测末页上界为 5104.294，释放时位置 5191.330
  原边界容差仅半个逻辑像素，拒绝了该正常释放
- 正确捕获释放后，旧参数栈槽又被原始配置查询复用
  页面对象已捕获到原始托管 Context，现由原始 Context 生产者和 physics 消费者解出活跃栈根与压缩字段
  当前镜像识别的活跃根为 FP 减 24，字段字节偏移为 19，均不是生产固定偏移

## 真机结果

- 负一屏开启时，末页释放直接回到桌面第一页，画面未进入负一屏
- 350 毫秒、1000 毫秒滑动分别确认末页到首页，内部应用计数随实际画面增加
- 临时关闭无限滚动，末页向外滑动仍停留在末页，requested 为零，未增加循环应用计数
- 重新开启开关，不重启桌面即恢复末页到首页
- 临时关闭负一屏，确认首页到末页的反向循环
- 150 毫秒快滑从末页回首页，实测释放速度 1701.434
  1000 毫秒慢滑从首页回末页，释放位置负 94.383，释放速度负 255.216
  两张最终画面分别为桌面第一页及最后一页，负一屏未成为跳转目标
- 当前进程最终记录 executions 40，edge_releases 6，internal_applied 5
  其中一次首屏释放保留了开启负一屏时的原生保护，未构造循环弹簧
- 完整复测期间桌面 PID 保持 12619，当前进程崩溃缓冲无崩溃记录

首屏右滑在负一屏开启时仍由原生负一屏接管
本次没有屏蔽或替换这条独立手势，关闭负一屏后双向桌面循环可用
这与末页回首页不经过负一屏是不同的路径
