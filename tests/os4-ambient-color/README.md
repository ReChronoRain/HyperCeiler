# OS4 ambient color resolver component

`AmbientColorResolverOS4` is one stateless, privately constructed resolver for the NC / DI lifecycle owner. `create(loader, needsStandard, needsOptimized)` verifies only the selected APIs and exposes the exact `mediaDataClass`. `resolve(context, mediaData, optimized)` must run on the owner's background task and returns an immutable `Colors(light, dark)` or `null`. A null result means unavailable and must retain the OEM state; it is not a successful color operation. This component does not decide whether a media background mode is enabled and never changes a holder/view or schedules a task.

The standard path binds the actual static `DrawableUtils.drawable2Bitmap(Drawable, int, int)` with requested dimensions zero. The OTA converter rejects nonpositive intrinsic dimensions before considering requested sizes, so valid dimensionless private ColorDrawable/ShapeDrawable/adaptive snapshots are instead drawn onto a bounded 112×112 ARGB_8888 Canvas. It invokes the original private `MiPalette.getPixels(int[], Bitmap, List)` with a fresh 25,088-element array and null rect list, then calls the separate `AmbientNativeColorOS4` bridge. It preserves the ROM float/sqrt/ceil/filter-false sampling algorithm, rejects invalid/overflowing dimensions and changed MAX_AREA, and returns the same color for light and dark. It never touches the ROM's static `pixels` array or invokes its shared native HCT method; the original array JNI signature is preflighted only as part of the expected ROM API shape.

The original ARM algorithm has mutable native histograms, so private Java pixels alone are insufficient. The dedicated bridge owns a verified separate vendor ELF instance and serializes its own calls; its native implementation, identity/loading/fault/concurrency proof are maintained separately under `os4-ambient-native-color`. The wrapper loads lazily on a standard-color background task. A native return value of zero means unavailable; a high word of one plus the low 32 ARGB bits represents success, including genuinely transparent zero. Load/JNI failure returns null and optimized color remains independent.

**Standard color contract:** both NC and DI use the explicitly initialized OS4 media algorithm, with tone/chroma 20/20 in the private instance. The complete actual DI attach calls `MiPalette.init()` (which initializes 20/20); the independent native audit binds that chain. This is a deliberate stable media-color choice for NC as well. It is **not** bit-for-bit emulation of the uninitialized global singleton before DI attach. Preserved real ART runs show three of four sample images differ against that uninitialized singleton, including its zero fallback. New positive comparisons must invoke the complete original Java `MiPalette.init()` first, rather than change expected colors or discard those failed runs. The module does not initialize, mutate, or synchronize the OEM singleton as part of production operation.

**Classloader/lifetime:** a real API37 ART probe confirmed a second concurrently live DexClassLoader cannot load the same already-loaded bridge path. The wrapper therefore exposes static synchronized `pauseForHotReload()` and `resumeAfterRejectedHotReload()`, sharing the exact same Class monitor as `ensureLoaded()`. An already loaded bridge refuses the pause even if private initialization or a color call later failed. An unloaded/failed generation can freeze before cleanup; no late background task may load it while frozen. The entry integration must reject migration before old-generation cleanup when pause fails; restart SystemUI to change that loaded standard backend. The host tests cover the wrapper protocol, not the surrounding entry integration.

The optimized path uses real `WallpaperColors` followed by `ColorScheme(WallpaperColors, true, 6)`, the actual `mAccent1` field, and the exactly 13 boxed-integer `allShades` entries. It returns indices 4 and 7 without filtering or renumbering the list. Style 6 is the actual SchemeContent branch; the old Style enum is absent. No replacement color algorithm is introduced.

Ownership is explicit. Album bitmaps, including hardware ones, are copied to private ARGB_8888 software storage; borrowed or helper bitmaps are never recycled. Known framework leaf drawables are separately created and mutated before conversion. Standard adaptive icons are assembled from private layers. Actual Fancy / Animating / MAML-adaptive getters supply already-created quiet images; these are also privately copied. If a MAML adaptive icon has no top quiet image, private static background/foreground layers are attempted. The resolver never clones a Fancy ConstantState, calls `prepareFancyDrawable`, obtains a shared renderer root, or ticks a borrowed animation. Static quiet images are not claimed to be pixel-equivalent to an animated frame. Unknown wrappers, absent required static layers, cycles, or unavailable snapshots use the original cross-user `NotificationUtil.acquireApplicationIcon` fallback; if that also cannot be safely snapshotted the result is null. These failures are not coverage successes.

The host suite compiles the complete production Kotlin, not a copied implementation. Android graphics/rendering and the ROM private pixel helper are adapters/transcription; native dispatch reaches a host JNI recorder using the exact static array/width/height signature. It does not execute proprietary HCT code, the actual Android graphics engine, hook registration, ART, or a device. The SDK compile has no host graphics stubs. Fresh DEX and native JNI registration extraction is read-only and binds the actual OTA files. These host results do not prove ELF isolation. Preserve native-owner evidence and the actual ART namespace tests separately. The first strict-NOLOAD bridge failed in a genuine child-OTA/parent-module topology; that failure remains recorded. A later public loaded-image snapshot design was tested with the same two-loader topology, without private namespace APIs. This ordinary-app experiment still does not prove a particular LSPosed/SystemUI namespace setup.

All phone, LSPosed injection, NC/DI rendering, work-profile behavior on hardware, restart recovery, and stability states remain `NOT_TESTED`.

The real Android probe uses unmodified complete OTA DEX classes, actual Bitmap/Canvas/WallpaperColors, and the original ARM library through the API37 emulator's native bridge. All proprietary APK/ELF/probe APK build products stay under `_local-only`. Ordinary app hidden-API access first failed; the separate authorized probe wrapper temporarily enables hidden APIs on only the dedicated AVD, restores the exact previous setting in `finally`, and records readback. This does not reproduce SystemUI permissions. Fancy input uses the exact ROM quiet getter on an allocated test object, not a live renderer. Its images prove static getter/snapshot behavior only.
