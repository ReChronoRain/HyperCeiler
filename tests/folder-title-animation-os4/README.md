# Independent folder title and close-animation contracts

`python tests/folder-title-animation-os4/run.py` uses the C++20 compiler in
`CXX` (or `c++`). The checked-in 9239 instruction fixture comes from the image
identified by `source_sha256`; addresses are test inputs, never runtime tables.

The title path validates current semantic TextAlign roots against each other,
derives Alignment.center from Android Gravity.CENTER, and checks the current
Container consumer and its fresh Insets producer. The anonymous text closure
must call the header's own text-style method. Parent ownership comes from the
current symbol span plus the validated Container/frame/directional diamond.
Only title slots 4, 5 and 7 are installed when unrelated grid geometry refuses.
The original full eight-slot bank remains available on images it validates.

The close-animation resolver also accepts a verified lazy singleton producer
whose two original branches merge into a register before the original Rx call.
It tracks register/local aliases through that merge and checks the same Rx
field and callee as the current configuration getter. Only an analysis copy is
normalized; no managed call, GC return PC or configuration field is moved.
The existing three scale and two cached-inset consumers must still all match.

Tests cover relocation, missing cache/init functions, changed singleton fields,
clobbered Rx aliases and missing title roots/ownership. The portable 7751
padding callback suite also covers the current horizontal Alignment constants,
editor/shared-padding rejection and disabled no-op behavior.

The medium switches had also activated the legacy shared landing-dimension
override even when small/large folder factors were neutral. The gate is now
scoped back to its original small/large controls. The actual capture callback
is tested with nine independent medium-factor combinations, a legacy scaled
pair, and invalidation of a previously captured pair when the same stack frame
is reused after disabling scaling. Medium-only controls cannot rewrite an
unscaled folder's landing rectangle.

The seven-site rendered-grid animation bank also accepts metric helpers when
the original cache calls each helper, boxes that same D0 result and stores it
into the animation controller. The binder proves each helper's currentConfig
producer, its metric load and return, and the padding getter's delegation.
The original inline-metric path is attempted first. No fixture address or
derived business-field offset is used as a runtime lookup table. Missing or
ambiguous owners/links leave the whole bank unpublished. `preview-9239.json`
contains fourteen original instruction bodies from the same source image.
The executable checks relocation and rejects missing owners, wrong links and
broken boxing/store consumers.

Device verification on 2026-11-15 used the newly built Release on the connected
24129PN74C, launcher process 25981. Its log confirms `bank bound=7` and actual
source corrections for indices 0..3 (X deltas 9.916, 3.305, -3.305, -9.916;
Y delta -3.305; scale ratio 1.0). Config receipt was `req=0x20000157` and the
independent title bank was bound and consumed. Configuration used the existing
`debug.hyperceiler.home_config_backend=root-socket` diagnostic setting; the
already-running system-server WMS endpoint was not reloaded or revalidated.

Private screen recordings remain in the host temporary directory, outside the
repository. Small, large, horizontal medium and vertical medium folders each
completed Back-close, reopen and outside-close cycles from confirmed folder
hit areas. The small-folder compact red preview was tracked at original frame
timestamps during both closing tails (1.68..2.60 and 4.08..5.60 seconds): maximum
adjacent Y change was 1.466912 screen pixels (8.51 ms interval). The other three
recordings were inspected visually; they do not have a quantified jump bound.
No large final snap was observed in these sampled cycles. This does not prove
all layouts, edit/drag states, expanded overflow hit areas, or older launcher
images are device-verified. Old direct parsing remains in place, but an old
launcher was not installed for a device comparison.
