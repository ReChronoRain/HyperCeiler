# OS4 Home shortcut management

Run `python3 run.py` in this directory. The fixtures contain executable words
from launcher 8583 and 8584, without symbol/section names. The production resolver
must prove the two regional metadata bool getters, shared bundle field and bool
bridge, prohibited-activity string getter, saved argument aliases, synchronous
qualification controller and its single asynchronous management-list consumer.
Each function is independently relocated and every contract instruction is
corrupted under ASAN/UBSAN. Missing, ambiguous and unexpected consumers decline.

Only the management list qualification entry returns canonical Dart true, as
the legacy Java feature did. Actual hide/restore confirmation and persistence,
uninstall predicates and launcher gestures are unchanged. The hook runs before
any Dart frame is entered and makes no allocation or Dart/GC call. The existing
full-register gateway preserves the managed x15 stack and native SP alignment.

Runtime discovery uses executable PT_LOAD contents. Instruction/register roles
and relative in-function control flow are narrow verified ARM64 Dart contracts,
not a promise of compatibility with every launcher build. Addresses, metadata
fields, frame slots and pool displacements are read from the current code.

Device validation still requires opening the entry from Home Other, checking a
previously filtered application, then hiding and restoring a disposable shortcut
while checking actual hit/applied counters and avoiding user layout changes.
