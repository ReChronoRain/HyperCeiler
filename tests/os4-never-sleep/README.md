# HyperOS 4 never-sleep option regression

Run `python3 tests/os4-never-sleep/run.py` from the source checkout. The runner compiles the **complete production** `UnlockNeverSleepScreenOS4.java` and the unmodified legacy `UnlockNeverSleepScreen.java`, and executes the callbacks against a deterministic host model. `--baseline` selects the legacy production rule instead; the target ROM has no `KeyguardTimeoutListPreference`, so it fails to register its constructor hook and 8 of the same 26 cases fail.

The preference fixture transcribes the relevant behavior of the supplied OS4 Settings APK `KeyguardTimeoutDropDownPreference.disableUnusableTimeouts()`, `updateDisableState()` and the selection write. The exact reviewed DEX smali, XML, localized array values, callers, APK hash and compile logs are under `acceptance/java-next/` in the parent workspace. The fixture deliberately models Android views, device policy access, SettingsProvider writes and hook dispatch; it is **not** an execution of the ROM class or a physical-device result. Its setter counter only proves that the production hook itself does not write the setting.

The cases cover OLED/LCD, an unavailable policy service as in the original method, normal and unusual nonzero managed limits, the separate `no_config_screen_timeout` restriction, selecting and retaining Never, 50 repeated callbacks, a newly added policy limit, independent preference instances, unknown/malformed option arrays, and failed field/method/policy reads. Failed or unknown inputs run the original behavior, including its existing exceptions; the hook does not promise to repair malformed future ROM data.

The independent actual-dependency compile uses the Android 37 SDK, real EzHook/libxposed/Kotlin dependencies and earlier Gradle-built module classes. It compiles the complete new rule and modified `SystemSettingsB` route. Test fixture compilation alone is not used as evidence of Android API compatibility.

Real-device menu rendering, persisted timeout behavior, LSPosed injection, restart recovery, and long-term stability remain **NOT_TESTED**. The root acceptance plan remains the physical-device test authority. Disabling the hook requires rebuilding the Settings scope/page under the module lifecycle; restore the original timeout first. An existing instance whose array was already shortened by an administrator restriction may need page recreation after the restriction is lifted. The rule never manufactures an absent Never option or bypasses a nonzero device-policy time limit.
